# Практикум: один проект, разные README

«Полка» — готовый учебный пример для написания документации. При использовании указывайте происхождение основы; ваш результат этой практики — README, а не авторство готовой программы.

Ветки отличаются **только файлом README.md**. Код, тесты и документация одинаковы. `main` содержит итоговый вариант. Плохие варианты нужны для разбора ошибок, а не для запуска команд из них.

| Ветка | Содержание README |
| --- | --- |
| `readme-00-assignment` | Исходное описание через учебное задание |
| `readme-01-intro` | Название, задача, пользователь, ценность, скриншот |
| `readme-02-scenarios` | Добавлены основные сценарии и роли технологий |
| `readme-03-run` | Добавлены Docker, локальный запуск, тесты и линтеры |
| `readme-04-navigation` | Добавлены карта проекта и ссылки для продолжения |
| `readme-05-final` | Добавлены статус и ограничения; совпадает с `main` |
| `variant-demo-first` | Другая допустимая подача: команды запуска сразу после описания |
| `anti-overpromise` | Намеренно неверные обещания и команда, которой в проекте нет |

## Начало работы

Git bundle — один файл с историей и ветками Git. Для него не нужен GitHub. Если вы получили `book-loan-tracker.bundle`, откройте терминал в каталоге с ним:

```bash
git clone -b main book-loan-tracker.bundle book-loan-tracker-workshop
cd book-loan-tracker-workshop
git switch -c my-readme origin/readme-00-assignment
```

Если вы работаете прямо в исходном репозитории с локальными учебными ветками, используйте `git switch -c my-readme readme-00-assignment`.

Теперь редактируйте свой README. Чтобы посмотреть образец, не переключая ветку и не теряя правки:

```bash
git show origin/readme-01-intro:README.md
git diff origin/readme-02-scenarios origin/readme-03-run -- README.md
```

В исходном репозитории вместо `origin/...` пишите `...`. Клонирование из bundle создаёт `origin`, указывающий на локальный bundle, а не на GitHub.

Не нужно менять имя самого репозитория при переходе между вариантами. Заголовок README и короткое описание можно сравнить в [вариантах названия](docs/names.md).

## Практика

Сначала откройте [инструкцию запуска](docs/development.md) и выполните [демонстрацию в браузере](docs/demo.md). Затем дополняйте README по этапам: первый экран → сценарии и стек → запуск → навигация → ограничения. Сравнивайте с соответствующей веткой после собственного варианта.

Результат — README, по которому можно понять назначение, запустить демо, проверить отказ в повторной выдаче и найти реализацию. Проверьте ссылки и каждую команду в новой копии проекта. Не добавляйте возможности, которых нет в коде.

## Если будете размещать пример на GitHub

Это локальный учебный репозиторий; публичный адрес и онлайн-демо не созданы. В [вариантах названия](docs/names.md) есть готовые название, короткое описание и темы для ручного оформления страницы. Инструкции урока работают без публикации. Для передачи всех веток используйте bundle: обычный архив файлов историю веток не содержит.
