# Устройство «Полки»

```text
Браузер → web.py → library.py → SQLite
Терминал → polka.py ↗
```

[web.py](../web.py) принимает HTTP-запросы и отправляет HTML из
[templates/index.html](../templates/index.html). Оформление находится в
[static/app.css](../static/app.css); JavaScript не используется.
Waitress запускает веб-приложение одним процессом с четырьмя потоками.

[polka.py](../polka.py) разбирает аргументы CLI. Оба интерфейса вызывают
[library.py](../library.py): `add()`, `lend()`, `give_back()`, `history()`.
Условия выдачи и возврата не дублируются в HTML или HTTP-обработчиках.

Веб-интерфейс открывает соединение на запрос и закрывает после ответа.
Изменение текущего читателя и добавление события выполняются в одной транзакции SQLite.
Перед проверкой доступности книги начинается транзакция записи: повторная выдача проверяется
по текущему состоянию базы, даже если браузер показывает устаревшую страницу.

`connect()` применяет [начальную SQL-схему](../migrations/001_initial.sql), которая создаёт
таблицы при их отсутствии. Автоматического обновления старой схемы и версионирования нет.
`books` хранит текущее состояние, `events` — последовательность выдач и возвратов.

См. [описание решения о хранении](decisions/001-storage.md),
[HTTP-маршруты](http.md) и [конфигурацию](development.md).

Форма подтверждения возврата передаёт номер выдачи. Он сверяется внутри транзакции: старая форма не может вернуть более новую выдачу. CLI возвращает текущую выдачу по номеру книги.
