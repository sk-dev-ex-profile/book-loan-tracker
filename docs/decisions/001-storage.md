# Хранение текущего состояния и истории

## Контекст

Для локального учебного сценария нужны список книг, текущий читатель и последовательность выдач и возвратов. Отдельный сервер базы усложнил бы запуск практики.

## Решение

Используется SQLite через стандартный модуль Python `sqlite3`. В `books` хранится текущий читатель, в `events` — события выдачи и возврата. Изменение читателя и добавление события выполняются в одной транзакции.

## Альтернатива и границы

Можно было сохранять данные в JSON-файл, но тогда согласованное обновление текущего состояния и истории пришлось бы организовать отдельно. Выбор SQLite здесь связан с локальным сценарием и доступными транзакциями; он не доказывает готовность к многопользовательской нагрузке.

Время событий не сохраняется. Порядок определяется их номерами. Нет механизма версионирования схемы и миграции старых баз. Проверку отката при ошибке записи события содержит `test_event_write_failure_rolls_back_loan` в [тестах](../../tests/test_cli.py).
